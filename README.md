# dak.gg '잡레이너'의 Plan-Do-See PDS 다이어리

## 1. 프로젝트 개요
* 본 프로젝트는 롤토체스(TFT) 플레이어 '잡레이너'의 랭크 게임 목표 및 연구 과정을 **계획(Plan) → 실행(Do) → 돌아보기(See)**로 체계화한 서비스입니다.
* Firebase Firestore / REST Database 스키마 규격(`contracts/pds-schema-v2.json`)에 맞춰 동작합니다.

---

## 2. 짧은 확인 방법 (Verification Steps - T06-C59)

1. **어디로 가나요?**
   * 프로젝트 폴더의 `index.html` 파일을 브라우저(시크릿 창)로 엽니다.
2. **세 단계 안에 무엇을 하나요?**
   * **1단계**: 메인 화면에서 '잡레이너'의 TFT 마스터 티어 계획 1개와 할 일 5개 항목을 확인합니다.
   * **2단계**: 할 일 항목 중 하나인 `[운영법] 잡레이너 계정 초반 패스트 8렙 운영...`의 완료 버튼을 연달아 두 번 누릅니다.
   * **3단계**: 하단 '돌아보기(See)' 섹션의 **'완료 수'** 또는 **'막힘 수'** 집계 카드의 숫자를 클릭합니다.
3. **무엇이 보이면 통과인가요?**
   * 완료 버튼을 연달아 눌러도 완료 수가 **1만 증가**하고, 집계 클릭 시 해당 조건의 할 일 목록으로 스크롤 및 필터링이 즉시 적용되면 통과입니다.
4. **안 될 때는 무엇이 보나요?**
   * 완료 수가 2 이상 중복 증가하거나, 집계 숫자를 클릭했을 때 목록 필터링 이동이 동작하지 않습니다.

## 3. 제출문 (Submission Document - T06-C60)

1. **AI에게 맡긴 일**:
   * Firebase Firestore 스키마 표준 규격(`contracts/pds-schema-v2.json`) 설계
   * Double-click 완료 처리 중복 방지 로직(Idempotency Guard) 구현
   * XSS 보안 처리를 위한 `escapeHTML` 유틸리티 함수 작성
2. **내가 직접 판단한 일**:
   * '잡레이너' 계정의 실제 TFT 패치(14.17) 연구 시나리오 및 5가지 할 일/3가지 실행 기록 정의
   * 서울 시간(KST) 기준 마감일 경과 여부에 따른 지연(Delayed) 상태 산출 기준 결정
   * 로그인 미적용 안내 배너 상단 고정 UI 배치
3. **AI 제안을 따르지 않은 일**:
   * AI는 로컬 스토리지에 데이터를 단순 덮어쓰는 방식을 권장했으나, T06-C08 기준(계획 수정 시 이전 계획 이력 보존) 충돌을 방지하기 위해 `plan_histories` 배열/컬렉션을 분리하여 과거 이력이 완벽히 보존되도록 직접 변경하였습니다.
